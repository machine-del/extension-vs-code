## 🏛️ Кодекс поведения

Мы обязуемся предоставить приветливую, безопасную и доступную среду для всех, независимо от:
- Возраста, размера тела, видимой или невидимой инвалидности
- Этнической принадлежности, идентичности и выражения
- Уровня опыта, образования, социально-экономического статуса
- Национальности, личного вида, расы, религии
- Сексуальной идентичности и ориентации

### Примеры поведения, способствующего созданию позитивной среды:

- Используйте приветливый и инклюзивный язык
- Будьте уважительны к различным мнениям и опыту
- Принимайте критику конструктивно
- Сосредоточьтесь на том, что лучше для сообщества
- Проявляйте эмпатию к другим членам сообщества

### Примеры неприемлемого поведения:

- Использование сексуализированного языка или образов
- Оскорбительные комментарии, основанные на личности
- Троллинг, оскорбительные комментарии, личные или политические атаки
- Публичное или частное преследование
- Публикация приватной информации без согласия

## 🚀 Как начать

### Предварительные требования

- Git установлен и настроен
- Node.js >= 18.x
- VS Code >= 1.120.0
- Базовые знания TypeScript

### Шаги для начала разработки

1. **Fork репозиторий**
   ```bash
   # На GitHub нажмите кнопку "Fork"
   ```

2. **Clone ваш fork**
   ```bash
   git clone https://github.com/YOUR-USERNAME/extension-vs-code.git
   cd extension-vs-code
   ```

3. **Добавьте upstream remote**
   ```bash
   git remote add upstream https://github.com/machine-del/extension-vs-code.git
   ```

4. **Создайте feature branch**
   ```bash
   git checkout -b feature/amazing-feature
   ```

5. **Установите зависимости**
   ```bash
   pnpm install
   ```

6. **Запустите разработку**
   ```bash
   pnpm run watch
   ```

## 🔧 Процесс разработки

### Структура проекта

```
src/
├── extension.ts          # Главная точка входа
├── middleware/
│   └── index.ts          # Регистрация модулей
├── modules/              # Логика модулей
└── data/                 # Конфигурация snippets
```

### Типичный workflow

1. **Создайте branch**
   ```bash
   git checkout -b feature/my-feature
   ```

2. **Внесите изменения**
   - Изменяйте код
   - Добавляйте новые файлы при необходимости
   - Сохраняйте соответствие стилю кода

3. **Протестируйте изменения**
   ```bash
   pnpm run compile
   pnpm run lint
   pnpm run check-types
   ```

4. **Commit и push**
   ```bash
   git add .
   git commit -m "feat: описание вашего изменения"
   git push origin feature/my-feature
   ```

## 📝 Стиль кода

### Форматирование

- **Язык**: TypeScript
- **Форматер**: ESLint
- **Размер отступа**: 2 пробела
- **Кавычки**: Двойные кавычки `"`
- **Точка с запятой**: Обязательна

### Правила ESLint

Перед commit убедитесь, что код проходит linting:

```bash
pnpm run lint
```

Для автоматического исправления:

```bash
pnpm run lint -- --fix
```

### Именование

- **Функции и переменные**: `camelCase`
- **Классы**: `PascalCase`
- **Константы**: `UPPER_SNAKE_CASE`
- **Файлы модулей**: `feature.module.ts`
- **JSON конфигурация**: `index.json`

### Примеры

```typescript
// ✅ Хорошо
export function UserModule() {
  const command = "extension-vs-code.user";
  const TIMEOUT = 5000;
  
  const handleClick = () => {
    // код
  };
}

// ❌ Плохо
export function userModule() {
  const cmd = "extension-vs-code.user";
  const timeout = 5000;
  
  const handle_click = () => {
    // код
  };
}
```

### Комментарии

- Комментируйте только сложную логику
- Используйте однострочные комментарии (`//`) для простых объяснений
- Используйте многострочные комментарии (`/* */`) для блокового описания

```typescript
// ✅ Хорошо
// Регистрируем провайдер автодополнения для PHP
const provider = vscode.languages.registerCompletionItemProvider("php", {...});

// ❌ Плохо - очевидный комментарий
// Создаем переменную command
const command = data.command;
```

## 📤 Процесс Pull Request

### Создание PR

1. **Убедитесь, что ваш branch актуален**
   ```bash
   git fetch upstream
   git rebase upstream/main
   ```

2. **Отправьте ваши изменения**
   ```bash
   git push origin feature/my-feature
   ```

3. **Откройте Pull Request**
   - На GitHub перейдите в ваш fork
   - Нажмите "New Pull Request"
   - Выберите `machine-del/extension-vs-code` как base
   - Выберите ваш branch как compare

### Шаблон PR описания

```markdown
## Описание
Кратко опишите цель этого PR.

## Связанные Issue
Closes #123

## Тип изменения
- [ ] Bug fix
- [ ] New feature
- [ ] Breaking change
- [ ] Documentation update

## Чеклист
- [ ] Мой код следует стилю этого проекта
- [ ] Я выполнил linting (`pnpm run lint`)
- [ ] Я выполнил type checking (`pnpm run check-types`)
- [ ] Я добавил комментарии к сложному коду
- [ ] Я обновил документацию, если необходимо

## Скриншоты (если применимо)
Добавьте скриншоты или видео для UI изменений.
```

### Требования для merge

- ✅ Все тесты пройдены
- ✅ Код проходит linting
- ✅ Нет конфликтов с main branch
- ✅ Минимум 1 одобрение от maintainer

## 🐛 Отчеты об ошибках

### Создание issue об ошибке

1. **Перейдите в Issues**
   - GitHub > Issues > New Issue

2. **Выберите шаблон "Bug Report"**

3. **Заполните информацию**

### Шаблон bug report

```markdown
## Описание ошибки
Кратко опишите, что не так.

## Шаги для воспроизведения
1. ...
2. ...
3. ...

## Ожидаемое поведение
Что должно было произойти?

## Фактическое поведение
Что на самом деле произошло?

## Окружение
- OS: Windows 10
- VS Code Version: 1.120.0
- Extension Version: 0.0.1

## Дополнительный контекст
Любая другая информация, которая может помочь.

## Логи
Скопируйте ошибку из консоли (Ctrl+Shift+`)
```
